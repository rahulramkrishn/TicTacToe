Implement the frozen P010.1 architecture for the Tic-Tac-Toe REST API and web/API integration.

P010.1 is the authoritative architectural baseline. Do NOT reinterpret, redesign, or weaken any of its decisions.

Implement only the API/Web layer required to expose the existing Domain and Application capabilities through HTTP.

## 2. Frozen P010.1 Decisions — MUST NOT CHANGE

### Player authority

`MakeMoveRequest` contains:

```json
{
  "player": "X",
  "cellIndex": 4
}
```

The `player` value is client-supplied because this is part of the frozen API contract.

However:

**`Game.CurrentPlayer` remains authoritative.**

The API must NOT allow the client to override the actual turn.

A mismatch must propagate as:

```text
HTTP 409 Conflict
INVALID_TURN
```

---

### Unknown JSON properties

Configure:

```text
JsonUnmappedMemberHandling.Disallow
```

Unknown properties must be rejected.

For example:

```json
{
  "player": "X",
  "cellIndex": 4,
  "row": 1
}
```

must NOT be silently accepted.

Return:

```text
400 Bad Request
MALFORMED_REQUEST
```

Do not silently ignore unknown properties.

---

### ArgumentException handling

Do NOT create a broad:

```text
ArgumentException -> 400
```

mapping.

Only explicitly identified client-input errors should map to `400`.

Unexpected internal argument failures must result in:

```text
500 Internal Server Error
INTERNAL_SERVER_ERROR
```

## 4. Correlation / Trace ID

Implement the frozen P010.1 behavior:

```text

```

For `ProblemDetails`, include:


The same trace ID must be used consistently for the response.

## 6. Application Boundary

Controllers must remain thin.

The intended flow is:

```text
HTTP Request
     ↓
Controller
     ↓
Application Service
     ↓
Domain Aggregate
     ↓
Domain Events
     ↓
Application Dispatcher / Handler
     ↓
Infrastructure Repository
     ↓
DTO Mapping
     ↓
HTTP Response
```

Controllers must NOT implement:

* win detection
* draw detection
* turn rules
* computer strategy
* undo rules
* scoreboard calculation
* domain state transitions

Those responsibilities already belong to Domain/Application layers.

## 12. Concurrency Tests

Implement the frozen P010.1 real HTTP concurrency tests.

### Same game

Send 10 concurrent requests targeting the same cell.

Expected:

```text
Exactly 1 -> 200 OK
Remaining 9 -> 409 CELL_OCCUPIED
```

Verify no state corruption.

### Computer mode

Send concurrent human move requests against the same Computer Mode game.

Verify:

```text
Human X move
    +
Computer O move
```

is treated as one serialized logical turn.

No orphan computer turns.

No duplicate moves.

No corrupted move history.

### Cross-game concurrency

Create multiple independent games and perform moves concurrently.

Verify different games do not unnecessarily block each other.
