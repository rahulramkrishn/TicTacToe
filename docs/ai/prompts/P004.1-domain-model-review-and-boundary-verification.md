P004 — Pure Domain Model Foundation has been completed and passed its automated test/build gate.

Before beginning P005 — Game Rules, perform a focused architectural and DDD review of the P004 implementation.

---

# 5. Review Board.Clone()

P004 currently exposes:

```text
Board.Clone()
```

Determine whether this is justified as a low-level defensive/snapshot primitive or whether it prematurely couples the domain model to the future Memento design.

Do NOT implement Memento.

If `Clone()` is retained, document:

* why it exists
* what guarantees it provides
* why it is not itself the Memento pattern
* how P006 will use/replace it

If it is not required by the specification and creates unnecessary coupling, remove it.

Do not make speculative changes.

---

# 6. Review IGameRepository placement

Inspect:

```text
IGameRepository
```

Determine where the repository abstraction belongs according to the documented architecture.

Explicitly compare:

```text
Domain
vs
Application
```

Consider:

* DDD aggregate persistence boundary
* dependency inversion
* current in-memory requirement
* Infrastructure implementation
* Application orchestration

If `04-ddd-and-domain-model.md` or `05-architecture.md` explicitly places the repository abstraction in Domain, keep it.

If the documentation places it in Application, move it.

If documentation is ambiguous:

* do not guess silently
* record the architectural decision
* choose the simplest option consistent with the documented dependency direction
* create/update an ADR only if an actual architectural decision is required
