# 1. Mandatory Corrections

### 1. Player Authority & Client Input
- `player` is client-supplied in `MakeMoveRequest` per `docs/06-api-contract.md`.
- `Game.CurrentPlayer` remains strictly authoritative on the server.
- If client supplies `player != Game.CurrentPlayer`, Domain raises `InvalidTurnException` $\rightarrow$ `409 Conflict` (`INVALID_TURN`).

### 2. Freeze Unknown JSON Property Behavior
- `JsonUnmappedMemberHandling = JsonUnmappedMemberHandling.Disallow`.
- Unknown properties (e.g. `"row"`, `"column"`, arbitrary extra fields) fail deserialization $\rightarrow$ `400 Bad Request` with code `MALFORMED_REQUEST`.

### 3. Remove Broad ArgumentException Mapping
- Only explicit client-input validation failures (e.g. `InvalidCellIndexException`, `JsonException`) map to `400 Bad Request`.
- Internal / general `ArgumentException` falls through to `500 Internal Server Error` with `INTERNAL_SERVER_ERROR`.

### 4. ProblemDetails Type URI Convention
- Canonical URI convention: `https://api.tictactoe.com/errors/{code-kebab-case}`.
- Examples: `https://api.tictactoe.com/errors/cell-occupied`, `https://api.tictactoe.com/errors/invalid-turn`, `https://api.tictactoe.com/errors/game-not-found`.

### 5. TraceId Generation & Correlation
- Trace identifier resolved via `Activity.Current?.Id ?? HttpContext.TraceIdentifier`.
- Correlates incoming `traceparent` or `X-Correlation-Id` header.
- Sets response header `X-Correlation-Id: {traceId}` and sets `"traceId"` field in RFC 7807 ProblemDetails payload.

### 6. DI Lifetime Verification
- Verify via integration tests:
  - `IGameRepository` $\rightarrow$ `InMemoryGameRepository` (Singleton)
  - `IScoreboardRepository` $\rightarrow$ `InMemoryScoreboardRepository` (Singleton)
  - `IComputerMoveStrategy` $\rightarrow$ `BasicComputerMoveStrategy` (Singleton)
  - `IDomainEventDispatcher` $\rightarrow$ `DomainEventDispatcher` (Singleton)
  - `IGameService` $\rightarrow$ `GameService` (Singleton — holds `ConcurrentDictionary<GameId, SemaphoreSlim>`)
  - `IScoreboardService` $\rightarrow$ `ScoreboardService` (Singleton)

### 7. Reset + Pending GameCompletedEvent Integration Test
- Play game to terminal win via API moves.
- Call `POST /api/games/{id}/reset`.
- Verify scoreboard reflects win.
- Verify reset returns clean game state under same `gameId`.
- Verify subsequent moves do not duplicate scoreboard update.

### 8. Strengthened Concurrency Tests
- Same-game concurrency: 10 parallel HTTP POST moves targeting the same cell (1 succeeds with 200; remaining return 409 Conflict).
- Computer Mode concurrency: concurrent human moves execute human + computer move atomically under `SemaphoreSlim`, preserving alternating turn history.
- Cross-game concurrency: distinct games execute in parallel without lock contention.
