# 2. Verify toolchain compliance

Determine:

| Tool | Required by specification | Actual | Compatible | Action |
| ---- | ------------------------- | ------ | ---------- | ------ |

Check:

* .NET SDK
* target framework
* Node.js
* npm
* Angular CLI
* Angular version
* TypeScript version
* test framework

Do NOT upgrade/downgrade anything simply because a newer version exists.

The specification is authoritative.

If the actual version differs from the specification, determine whether the difference is:

1. explicitly allowed,
2. compatible and justified,
3. or a deviation.

If it is a deviation, correct it only if doing so is safe and clearly required.

Document the decision.

# 3. Verify .NET project dependency direction

Inspect every `.csproj`.

Produce the actual dependency graph.

Compare it against `docs/05-architecture.md`.

Pay particular attention to:

```text

Application
Infrastructure
API

```

Determine whether:

```text

```

is actually required by the architecture.

Do NOT change the dependency structure merely because of personal architectural preference.

If it contradicts the documented architecture:

* correct it,
* explain the correction,
* update ADR-008 if appropriate,
* update the implementation log.

If it matches the specification:

* leave it unchanged.

# 6. Investigate npm installation workaround

Inspect the package installation history and current dependency tree.

Determine why:

```text
npm install
```

initially failed.

Determine whether:

```text
npm install --legacy-peer-deps
```

was actually necessary.

Record:

* original error
* root cause if determinable
* workaround
* resulting dependency state
* whether the workaround should remain part of documented setup

Do not silently hide the workaround.

If the dependency tree is healthy and standard installation now works, verify that.

Do not change dependencies simply to eliminate historical noise.

---

# 7. Verify reproducibility

From a clean state, verify that the documented build commands work.

Backend:

```text
dotnet restore
dotnet build backend/TicTacToe.sln
dotnet test backend/TicTacToe.sln
```

Frontend:

```text
npm ci
npm run build
npm test -- --watch=false
```

Use the correct working directory/commands for Windows if necessary.

If `npm ci` cannot reproduce the environment, investigate why.

Do not immediately fall back to `npm install`.

The goal is reproducible setup.
