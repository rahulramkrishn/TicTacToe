# P011.0 Review — Angular Presentation Layer Architecture & Implementation Plan

## 1. Executive Summary

Phase **P011.0** establishes the architectural foundation, component hierarchy, reactive state management design, and implementation plan for the **Angular Presentation Layer** (Phase P011).

In accordance with strict repository governance:
- **Zero application or UI code has been implemented in this phase.**
- The architectural boundary between Angular and backend REST API is frozen.
- The plan is submitted for human review prior to any implementation.

---

## 2. Architecture & Boundary Verification

### 2.1 The Architectural Invariant
```text
Angular UI (Presentation Layer)
    │
    │ HTTP only (JSON / ProblemDetails)
    ▼
REST API (TicTacToe.Api — P010.2)
    │
    ▼
Application Layer (TicTacToe.Application — P009)
    │
    ▼
Domain Layer (TicTacToe.Domain — P001–P008)
```

1. **Frontend Has Zero Business Rules**:
   - Win detection is strictly performed server-side via `WinDetector`.
   - Draw detection is strictly performed server-side.
   - Computer move selection is strictly executed server-side via `IComputerMoveStrategy`.
   - Undo memento restoration is strictly executed server-side.
   - Scoreboard counter updates are strictly triggered server-side via `GameCompletedEvent`.
2. **Authoritative State Consumption**:
   - The UI is purely a reactive consumer of the backend's authoritative `GameStateDto` and `ScoreboardDto`.
3. **Canonical Cell Addressing**:
   - The frontend communicates solely in `cellIndex` (`0..8`).
   - Coordinate conversions (`row`, `column`) exist purely for user presentation in the move history log and cell accessibility labels.

## 3. Component & State Management Design

### 3.1 Component Hierarchy
- `App` (Shell / Layout container)
  - `HeaderComponent` (Title, Mode selector)
  - `StatusBannerComponent` (Turn indicator, Winner announcement, Draw notification)
  - `GameBoardComponent` (3x3 grid, cell states, winning cell highlight)
  - `GameControlsComponent` (Undo, Reset Game, New Game)
  - `ScoreboardComponent` (X Wins, O Wins, Draws, Reset Scoreboard)
  - `MoveHistoryComponent` (Chronological move log with derived row/column display)

### 3.2 State Management via Angular 21 Signals (`GameFacade`)
- Avoids over-engineering (no NgRx needed for this bounded scope).
- Native signals (`signal`, `computed`) provide fine-grained reactivity, optimal change detection, and zero unnecessary re-renders.
- Fully encapsulates HTTP service calls (`GameApiService`, `ScoreboardApiService`).
- Seamlessly maps RFC 7807 `ProblemDetails` error responses into dismissible user alerts.

## 4. UI/UX & Design System Guidelines

- Premium dark-theme design with deep slate/indigo glassmorphic cards.
- Distinct color coding: Sky Blue (`#38bdf8`) for X, Coral Rose (`#f43f5e`) for O, Emerald Green (`#10b981`) for winning lines.
- Responsive layout supporting viewports from desktop down to mobile.
- Full keyboard navigation, visible focus rings, and WCAG-compliant ARIA labels on all interactive cells.
