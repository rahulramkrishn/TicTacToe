## Dependency Compliance
- Initial scaffolding included an unnecessary project reference from `TicTacToe.Infrastructure` to `TicTacToe.Application`.
- In pure DDD, aggregate repository interfaces (`IGameRepository`, `IScoreboardRepository`) belong to `TicTacToe.Domain`.
- `TicTacToe.Infrastructure` was decoupled from `TicTacToe.Application`.
- **Actual Dependency Graph**:
  ```text
  TicTacToe.Domain (Pure Core)
         ▲                   ▲
         │                   │
  TicTacToe.Application      │
         ▲                   │
         │                   │
  TicTacToe.Api ──────► TicTacToe.Infrastructure
         ▲
         │
  TicTacToe.Tests (References Domain, Application, Infrastructure, Api)
  ```
- Dependency direction is inward toward the Domain, with zero cyclic dependencies.

## Deviations Found
1. **Infrastructure Reference Coupling**: `TicTacToe.Infrastructure.csproj` initially referenced `TicTacToe.Application.csproj`.
2. **Lockfile Synchronization**: Initial `package-lock.json` generated with `--legacy-peer-deps` lacked 3 optional native binding dependencies (`@emnapi/*`), causing strict `npm ci` to require a lockfile update.

## Corrections Made
1. Removed `ProjectReference` to `TicTacToe.Application` from `TicTacToe.Infrastructure.csproj`. Documented in ADR-008.
2. Synchronized `frontend/package-lock.json` so that standard `npm ci` executes without flags and exits with code 0.
