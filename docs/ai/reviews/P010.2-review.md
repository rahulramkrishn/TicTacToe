# P010.2 Review — API / Web Layer Implementation

## 1. Executive Summary

Phase **P010.2** establishes the **API / Web Layer** for the Tic-Tac-Toe assessment, exposing the existing Domain and Application layer capabilities via ASP.NET Core REST controllers and middleware without duplicating business rules.

This implementation strictly adheres to `docs/06-api-contract.md`, the approved architecture, and all 20 Principal-level review corrections and directives from `P010.1`:
1. **Thin Controllers**: `GamesController` and `ScoreboardController` contain zero business logic or rule validation. They translate HTTP transport representations into application commands and return canonical DTOs.
2. **Canonical Cell Addressing**: Operates strictly on `cellIndex` (`0..8`). No alternative `row`/`column` representations are accepted.
3. **Strict Unknown Property Rejection**: `JsonUnmappedMemberHandling.Disallow` and custom `InvalidModelStateResponseFactory` ensure payloads with unrecognized properties (such as `row`, `column`, or random keys) are rejected with HTTP 400 `MALFORMED_REQUEST`.
4. **Authoritative Turn Enforcement**: `Game.CurrentPlayer` is authoritative. Any client-supplied mismatched player in `MakeMoveRequest` is rejected with HTTP 409 `INVALID_TURN`.
5. **Standardized RFC 7807 ProblemDetails**: Custom `ExceptionHandlingMiddleware` produces uniform problem details with the agreed URI convention (`https://api.tictactoe.com/errors/{kebab-case}`), machine-readable `code`, HTTP `status`, `title`, `detail`, `instance`, and `traceId`.
6. **Removed Broad ArgumentException Mapping**: Only explicit client-input domain/application exceptions map to 400/409. Unexpected exceptions fall through to HTTP 500 `INTERNAL_SERVER_ERROR` with sanitized detail and zero stack trace leakage.
7. **Trace ID & Correlation**: Supports incoming `X-Correlation-Id` header, falls back to `Activity.Current?.Id ?? HttpContext.TraceIdentifier`, and returns it in both the `X-Correlation-Id` response header and ProblemDetails body.
8. **Preserved Per-Game Concurrency**: `GameService` is registered as a **Singleton** in DI so its internal `ConcurrentDictionary<GameId, SemaphoreSlim>` survives across HTTP requests, guaranteeing thread-safe per-game serialization across concurrent requests.
9. **Event Dispatch Integrity on Reset**: Resetting a game with a pending `GameCompletedEvent` drains and dispatches the event before clearing aggregate state, updating the session scoreboard reliably.
10. **Architecture Boundaries**: Onion architecture strictly enforced and verified via reflection tests. Domain has 0 outer references; Application has 0 Infrastructure/Api/AspNetCore references; Infrastructure does not reference Api; Controllers only depend on application service interfaces.

All **233 backend tests** and **2 frontend tests** pass with **0 warnings and 0 errors**.

## 2. Implemented Components

### 2.1 API Request DTOs (`TicTacToe.Api/Models/ApiRequests.cs`)
- `CreateGameRequest(GameMode Mode = GameMode.TwoPlayer)`
- `MakeMoveRequest(Player Player, int CellIndex)`
- Strictly canonical per `docs/06-api-contract.md`.

### 2.2 Error Handling Middleware (`TicTacToe.Api/Middleware/ExceptionHandlingMiddleware.cs`)
- Intercepts all unhandled exceptions in the HTTP pipeline.
- Extracts/propagates `traceId` and sets `X-Correlation-Id` response header.
- Maps domain and application exceptions to RFC 7807 ProblemDetails:
  - `GameNotFoundException` -> 404 `GAME_NOT_FOUND` (`https://api.tictactoe.com/errors/game-not-found`)
  - `InvalidCellIndexException` -> 400 `INVALID_CELL_INDEX` (`https://api.tictactoe.com/errors/invalid-cell-index`)
  - `JsonException` / `BadHttpRequestException` -> 400 `MALFORMED_REQUEST` (`https://api.tictactoe.com/errors/malformed-request`)
  - `CellOccupiedException` -> 409 `CELL_OCCUPIED` (`https://api.tictactoe.com/errors/cell-occupied`)
  - `InvalidTurnException` -> 409 `INVALID_TURN` (`https://api.tictactoe.com/errors/invalid-turn`)
  - `GameAlreadyCompletedException` -> 409 `GAME_ALREADY_COMPLETED` (`https://api.tictactoe.com/errors/game-already-completed`)
  - `CannotUndoException` -> 409 `CANNOT_UNDO` (`https://api.tictactoe.com/errors/cannot-undo`)
  - Unhandled/Unexpected -> 500 `INTERNAL_SERVER_ERROR` (`https://api.tictactoe.com/errors/internal-server-error`) with sanitized message: `"An unexpected error occurred. Please try again later."`

### 2.3 REST Controllers (`TicTacToe.Api/Controllers/`)
- **`GamesController.cs`**:
  - `POST /api/games` -> 201 Created with `Location` header (`/api/games/{gameId}`) and `GameStateDto`.
  - `GET /api/games/{gameId:guid}` -> 200 OK with `GameStateDto`. Strictly side-effect free.
  - `POST /api/games/{gameId:guid}/moves` -> 200 OK with `GameStateDto`. Rejects invalid body with 400.
  - `POST /api/games/{gameId:guid}/undo` -> 200 OK with `GameStateDto`.
  - `POST /api/games/{gameId:guid}/reset` -> 200 OK with `GameStateDto`. Preserves existing `gameId`.
- **`ScoreboardController.cs`**:
  - `GET /api/scoreboard` -> 200 OK with `ScoreboardDto`. Side-effect free.
  - `POST /api/scoreboard/reset` -> 200 OK with `ScoreboardDto` zeroed. Does not mutate active games.

### 2.4 Application Host & Pipeline Configuration (`TicTacToe.Api/Program.cs`)
- Configures controllers with `JsonStringEnumConverter`, `JsonUnmappedMemberHandling.Disallow`, and `CamelCase`.
- Configures `ApiBehaviorOptions.InvalidModelStateResponseFactory` to return RFC 7807 ProblemDetails with `MALFORMED_REQUEST` code and `traceId`.
- Configures CORS policy (`Cors:AllowedOrigins` defaults to `http://localhost:4200`).
- DI registrations:
  - `IGameRepository` -> `InMemoryGameRepository` (Singleton)
  - `IScoreboardRepository` -> `InMemoryScoreboardRepository` (Singleton)
  - `IComputerMoveStrategy` -> `BasicComputerMoveStrategy` (Singleton)
  - `IDomainEventDispatcher` -> `DomainEventDispatcher` with `GameCompletedEventHandler` registered (Singleton)
  - `IGameService` -> `GameService` (Singleton — holds per-game `SemaphoreSlim` locks)
  - `IScoreboardService` -> `ScoreboardService` (Singleton)
- Swagger / OpenAPI documentation configured for Development environment.
- Health check endpoint mapped at `/health`.
