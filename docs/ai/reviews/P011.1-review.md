# P011.1 Review — Angular Presentation Layer Plan Correction & Freeze

## 1. Executive Summary

Phase **P011.1** applies all 8 Principal-level review corrections to the P011.0 Angular Presentation Layer plan and formally freezes the architectural specification for Phase P011.

- **Zero application code, components, or templates were modified in this phase.**
- The architectural boundary between Angular and the REST API remains absolute.
- All 8 corrections have been reconciled and verified against `docs/06-api-contract.md` and P010.2.

---

## 2. Review Corrections Reconciliation

| # | Item | Frozen P011.1 Specification | Verification Method |
|---|---|---|---|
| 1 | **Computer Mode Semantics** | One UI click → one HTTP request (`POST /api/games/{id}/moves`). Backend executes human X + computer O atomically. Frontend never makes a second call. | `GameFacade` test asserting exactly 1 HTTP POST per human move in Computer Mode. |
| 2 | **Error Model Preservation** | Complete RFC 7807 `ProblemDetails` (`type`, `title`, `status`, `code`, `detail`, `instance`, `traceId`) modeled and preserved. | Facade test inspecting `error()` signal properties against mock error response. |
| 3 | **Operation-Safe Loading** | In-flight loading guard disables board, undo, reset, and new game controls. Duplicate calls dropped. Reset in `finalize()`. | Facade test asserting rapid duplicate calls are dropped while loading is true. |
| 4 | **Initialization Failure** | Failed `initGame()` / `newGame()` renders no fake game. Displays error alert with retry button. | Facade test verifying `gameState()` is null and `error()` is populated on HTTP 500. |
| 5 | **Scoreboard Sync** | Hydrated strictly from backend (`GameStateDto.scoreboard` or `/api/scoreboard`). Never computed locally. | Facade test asserting scoreboard updates from API response. |
| 6 | **Reset Game Semantics** | Calls `POST /api/games/{id}/reset`, preserves `gameId`, updates board/history. | Facade test verifying `gameId` is unchanged after `resetGame()`. |
| 7 | **New Game Semantics** | `newGame(mode)` calls `POST /api/games`, creates new session with new `gameId`. | Facade test verifying `gameId` changes after `newGame()`. |
| 8 | **Testable Accessibility** | Semantic `<button>` elements, dynamic ARIA labels, `aria-disabled`, visible focus rings, live region for announcements. | Automated DOM assertion tests in `game-board.spec.ts` and `status-banner.spec.ts`. |

---

## 3. Boundary Affirmation

The `GameFacade` is strictly a presentation coordinator. It **must not**:
- Implement win detection or winning cell evaluation.
- Implement draw detection.
- Implement legal move validation (other than disabling occupied buttons).
- Implement turn switching.
- Implement computer strategy.
- Implement undo memento management.
- Implement score calculations.
